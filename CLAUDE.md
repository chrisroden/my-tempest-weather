## Project

SwiftUI app for a WeatherFlow Tempest station, targeting iOS/iPadOS 17+ and macOS 14+ via Mac Catalyst (single target `MyTempestWeather`, bundle ID `com.chrisroden.MyTempestWeather`). It calls the WeatherFlow REST and WebSocket APIs directly. It is the Apple counterpart to the .NET/Avalonia project at `~/Repos/Personal/tempest-weather-pi-console/` (reference only, do not modify). It has no dependency on that project's Pi backend.

`COPILOT_CONTEXT.md` has a longer write-up: API details, storage keys, the TODO list and conventions. Update it when you change architecture or conventions.

## Build

No test target, no SwiftPM packages, no linter. `*.xcscheme` is gitignored, so the `MyTempestWeather` scheme is autogenerated.

```bash
# Mac Catalyst build (works without a simulator)
xcodebuild -project MyTempestWeather.xcodeproj -scheme MyTempestWeather \
  -destination 'platform=macOS,variant=Mac Catalyst' build

# iOS simulator build
xcodebuild -project MyTempestWeather.xcodeproj -scheme MyTempestWeather \
  -destination 'generic/platform=iOS Simulator' build
```

To run: open `MyTempestWeather.xcodeproj` and set a signing team. On first launch the Settings sheet asks for the API token, station ID and device ID.

## Architecture

- **Single ViewModel.** `WeatherViewModel` is `@Observable @MainActor`. It is created once in `MyTempestWeatherApp` and injected with `.environment(viewModel)`. Views read it with `@Environment(WeatherViewModel.self)`. Do not use `ObservableObject` or `@StateObject`.
- **Two data sources merged in the ViewModel.**
  - REST: `TempestAPIService.fetchForecast()` hits `better_forecast`. It runs on a `Task.sleep` loop (`startAutoRefresh`) and returns values already in the user's chosen units, because the unit prefs are passed as query params.
  - WebSocket: `TempestWebSocketService` subscribes to `rapid_wind` (~3 s) and `obs_st` (~1 min). Its values arrive in metric/SI units and are stored in the ViewModel's `live*` fields.
  - Display properties use the live value when one exists, otherwise the REST value. Live values must be converted to the user's units in the ViewModel (`convertWindMps`, `convertTempC`, `convertPrecipMm`). `livePressureMb` currently goes through unconverted.
  - `obs_st` array indices used: `[3]` gust, `[6]` pressure, `[7]` temp °C, `[8]` humidity, `[10]` UV, `[18]` precip day mm.
- **Locations.**
  - `WeatherViewModel.selection` (`LocationSelection`) picks the source. `.station` uses Tempest REST and the WebSocket. `.currentLocation` and `.saved(id)` use `WeatherKitService`.
  - `WeatherKitService` maps WeatherKit data into the same `ForecastResponse` model, converting to the user's units and to WeatherFlow icon slugs, so views don't branch on the source. Station-only extras (live WebSocket values, the lightning tile) are gated on `isStationSelected`.
  - Saved locations store a time zone from MapKit, because WeatherKit doesn't return one. `DailyForecast`/`HourlyForecast.timeZoneIdentifier` is set only on the WeatherKit path, so labels show the location's local time.
  - Tempest's own API can't serve arbitrary locations. A personal token gets 401 for `lat`/`lon`, and the official app uses a private, Firebase-authenticated host. Don't retry that route.
  - WeatherKit requires the `com.apple.developer.weatherkit` entitlement, the capability turned on for the bundle ID in the developer portal, and `WeatherAttributionView` shown with WeatherKit data.
  - New services use protocols in `Interfaces/` (`I{ServiceName}`).
- **Lifecycle.** `DashboardView` starts and stops auto-refresh and the WebSocket. `SettingsView.save()` restarts both after saving. The WebSocket needs `deviceId > 0` (station ID alone is not enough). It reconnects with exponential back-off capped at 60 s and pings every 30 s.
- **Storage.**
  - The API token is kept in the Keychain only (service `com.chrisroden.MyTempestWeather`, account `WeatherFlowApiToken`). Never store it in `UserDefaults`.
  - Everything else goes in `UserDefaults` under keys prefixed `WeatherFlow.`: `stationId`, `deviceId`, `refreshIntervalMinutes`, `tempUnits`, `windUnits`, `pressureUnits`, `precipUnits` and `distanceUnits`. `savedLocations` and `selectedLocation` are stored as JSON by `LocationStore`.
  - Unit keys are read with string literals in several files (`TempestAPIService`, `WeatherViewModel`, `SettingsView`, `WeatherKitService`). Keep them in sync.
- **Layout.** In `ContentView`, iPhone (`userInterfaceIdiom == .phone`) gets a `TabView`. iPad and Mac get a `NavigationSplitView` with a sidebar. `ForecastView` scales up for iPad and Mac.
- **Icons.** In `WeatherModels.swift`, `String.sfSymbol` and `iconTint` map WeatherFlow icon slugs (e.g. `clear-day`) to SF Symbols and colors. `WeatherIconView` enforces palette colors.

## Conventions

- Apple SDK only. No third-party packages.
- Views must not hardcode unit symbols. Use the ViewModel's `tempUnitSymbol`, `windUnitSymbol`, `pressureUnitSymbol` and `precipUnitSymbol`.
- New metric tiles follow the private `MetricTile` struct in `MetricsView.swift`.
- New forecast rows and cards follow the private `DayRow` and `HourCard` structs in `ForecastView.swift`.
